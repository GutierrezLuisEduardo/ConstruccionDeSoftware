1. ¿Qué ventajas ofrecen las variables CSS sobre los valores hardcodeados?

Permiten parametrizar valores que de otra manera se repetirían innecesariamente.

2. ¿En qué casos conviene declarar variables CSS fuera del selector :root?

Cuando sea de interés introducir cambios locales o por componente, que no afecten a todos los elementos.

3. ¿Cómo se pueden utilizar las variables CSS para implementar un sistema de temas (como modo oscuro)?

Después, simplemente se hace un toggle con javascript que da lugar al 'toggle' de ese tema, tras desencadenarse de alguna manera (pudiera ser un botón).

4. ¿Qué sucede cuando intentas usar una variable CSS que no ha sido declarada?

Se mantiene la propiedad establecidad por defecto o previamente declarada.

5. ¿Cuál es la diferencia entre los enfoques mobile-first y desktop-first?

El tipo de dispositivo que prioritizan para el desarrollo de su interfaz (se hace en torno a este).

6. ¿Qué breakpoints son los más comunes y por qué?

320–375px, 414–480px, 600–768px, 768–1024px, 1024–1280px, 1280–1440px+: para teléfonos pequeños, grandes; tablets pequeñas, grandes; laptops y desktop, respectivamente.

Son patrones comunes de diseño y pudiera decirse que son una especie de "estándar" en las respectivas industrias, de dichos dispositivos, el manejar dichas medidas para sus pantallas.

7. ¿Cómo afecta el viewport meta tag al diseño responsivo?

Contiene información como el ancho y alto. Que permite identificar las configuraciones adecudas para ese tipo de dispositivo.

8. ¿Qué técnicas además de media queries existen para crear diseños responsivos?

Usar medidas relativas al viewport y configuración del usuario, utilizar contenedores de distinto tipo para la distribución espacial, etc.

9. ¿Cómo puedes identificar qué regla CSS está siendo aplicada cuando hay múltiples selectores?

A partir de la especificidad de la regla, el orden de la declaración y si utiliza '!important'.

10. ¿Qué información proporciona la pestaña Computed en DevTools?

El margen, borde, padding y dimensiones de algún elemento seleccionado; También muestra en la parte inferior los resultados de la interpretación del código, utilizados para renderizar el elemento.

11. ¿Cómo puedes simular diferentes dispositivos sin tener acceso físico a ellos?

Cambiando la string del agente de usuario o seleccionando/creando un nuevo dispositivo desde la device toolbar de chrome o su equivalente en otros navegadores.

12. ¿En qué situaciones es preferible usar Bootstrap sobre Tailwind CSS y viceversa?

Bootstrap para utilizar elementos prefactorizados, quizá en la elaboración de un prototipo rápido; Tailwind CSS para produndizar en la personalización de los átomos.

13. ¿Qué significa que Tailwind sea "utility-first"?

Que proporciona pequeñas clases de CSS para un solo propósito y no escribir código personalizado por componente.

14. ¿Cómo afecta el uso de un framework CSS al tamaño final del bundle?

Añade más componentes por cargar y eso puede aumentarlo en mayor o menor medida, dependiendo del framework.

15. ¿Es posible combinar múltiples frameworks CSS en un mismo proyecto? ¿Por qué sí o por qué no?

Sí, es posible pero debe tenerse cuidado al gestionar qué componentes se importan y que estos no generen conflictos con los de otros frameworks.
