Testimonio de negociación con el Socio Formador.

Cuando el socio formador nos pidió implementar una API para la carga de información de cliente, le dije que someteríamos a evaluación esa posibilidad, pues considerando el tiempo que tenemos para entregar el sistema, pareciera más rápido limitar la funcionalidad de carga KYC al uso de un parser CSV y no de una API, pero bien podría ser factible si resultamos tener tiempo restante.

El socio formador nos lo concedió y a cambio nosotros decidimos implementar una vista especializada en lugar de requerir la subida de archivos JSON, por parte del Oficial de Cumplimiento, para la parametrización de reglas.



Testimonio de negociación en equipo.

Cuando le propuse a mi compañero la implementación de un sistema de reglas robusto que se encargara del desencadenamiento de la creación de alertas (requeridas por la ley, de recordatorio o personalizadas), reportes (los 4 tipos de reportes requeridos por la ley) y el monitoreo de los clientes a través de su perfilamiento transaccional (asignar grupos de clientes a reglas), él no se mostraba muy convencido pues aunque la propuesta fue sólida, consideraba que desarrollar este sistema se llevaría demasiado esfuerzo.

Le hice ver que, aunque lo que observó es verdad, en realidad también simplificaría e incluso abarcaría el cumplimiento de muchas de las funcionalidades una vez que estuviera terminado.

A cambio, yo concedí varias de sus propuestas para las vistas de la interfaz web y para las convenciones de codificación tanto para web como para BD.
